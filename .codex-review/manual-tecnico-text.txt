011 [Heading 1] 1. Introducción
012 [(sin estilo)] SYSTEMACT es una aplicación web interna que permite a Conviventia registrar, transferir, dar de baja y auditar los activos físicos de la organización. Reemplaza un sistema legacy en PHP/MySQL por un stack moderno basado en Next.js y Supabase.
013 [Heading 2] 1.1. Alcance
014 [(sin estilo)] Este documento cubre la información técnica necesaria para instalar, configurar, mantener y extender el sistema. No es un manual de uso final — para eso ver el Manual de Usuario.
015 [Heading 2] 1.2. Audiencia
016 [(sin estilo)] Personal técnico de Conviventia y futuros desarrolladores que reciban el sistema.
017 [Heading 1] 2. Stack tecnológico
019 [Heading 2] 2.1. Justificación
020 [List Paragraph] Next.js 15 con Server Components y Server Actions elimina la necesidad de mantener una API REST separada para mutaciones.
021 [List Paragraph] Supabase unifica Postgres, Auth y Storage; la lógica crítica vive en RPCs PL/pgSQL.
022 [List Paragraph] TypeScript estricto + Zod garantiza tipado en cliente, servidor y validación de entrada.
023 [Heading 1] 3. Arquitectura general
024 [(sin estilo)] El sistema se compone de un frontend Next.js desplegado en Vercel y un backend Supabase (PostgreSQL + Auth + Storage). El cliente se comunica con la BD a través del SDK oficial de Supabase, y todas las mutaciones críticas pasan por Server Actions que invocan RPCs PL/pgSQL.
025 [Heading 2] 3.1. Capas de seguridad
026 [List Paragraph] RLS (Row-Level Security) en cada tabla — frontera de la base de datos.
027 [List Paragraph] RPCs security invoker que invocan require_rol_escritura() o require_rol_admin() antes de mutar datos.
028 [List Paragraph] Guards de página (requireRol) y validaciones en Server Actions — defensa en profundidad.
029 [Heading 2] 3.2. Flujo típico de una mutación
030 [(sin estilo)] Usuario → Form (cliente, valida con Zod)
031 [(sin estilo)] → Server Action (re-valida con Zod, obtiene user)
032 [(sin estilo)] → RPC PL/pgSQL (require_rol_*, lock, insert + log)
033 [(sin estilo)] → revalidatePath()
034 [(sin estilo)] → toast Sonner

121 [Heading 1] 6. Base de datos
122 [Heading 2] 6.1. Modelo de datos
124 [Heading 2] 6.2. Reglas clave del modelo
125 [List Paragraph] Código de bien generado por generar_codigo_bien(prefijo) con formato PREFIJO-AÑO-NNN (ej. COMP-2026-001).
126 [List Paragraph] bienes.valor_total es columna GENERATED (cantidad × valor_unitario); nunca se envía desde el cliente.
127 [List Paragraph] bienes.estado ∈ { ACTIVO, INACTIVO, DE BAJA }. Un bien nunca se borra físicamente; las bajas son soft delete.
128 [List Paragraph] responsable_texto se usa cuando el responsable no existe en profiles (texto libre).
129 [List Paragraph] transferencias.area_origen y area_destino son text (no FK) para preservar historial legible aunque se renombre un área.

140 [Heading 2] 6.6. Almacenamiento (Storage)
141 [(sin estilo)] Bucket bienes — público, máximo 5 MB, formatos image/jpeg | png | webp:
142 [List Paragraph] SELECT abierto para mostrar imágenes con URL pública.
143 [List Paragraph] INSERT/UPDATE/DELETE solo authenticated.
144 [List Paragraph] Las imágenes se suben directamente desde el cliente (evita el límite de 4.5 MB de Server Actions en Vercel).
145 [List Paragraph] Nombre de archivo: {crypto.randomUUID()}.{ext} en raíz del bucket.
146 [Heading 1] 7. Módulos funcionales
148 [Heading 2] 7.1. Reglas de negocio destacadas
149 [List Paragraph] Transferencias: solo bienes ACTIVO. No se permite transferir a la misma combinación sede + área + responsable.
150 [List Paragraph] Bajas: solo bienes ACTIVO, solo ADMINISTRADOR. Transacción atómica que cambia el estado, registra en bajas e inserta en movimiento_bienes.
151 [List Paragraph] Auditoría: cada operación (REGISTRO, MODIFICACION, TRANSFERENCIA, BAJA) deja un registro escrito por el RPC correspondiente.
152 [List Paragraph] Último admin activo: las RPCs actualizar_rol_usuario y set_usuario_activo validan que la operación no deje el sistema sin administradores.

202 [Heading 1] 12. Convenciones de código
204 [Heading 2] 12.1. Reglas duras
205 [List Paragraph] TypeScript strict. Prohibido any (preferir unknown).
206 [List Paragraph] Server Components por defecto. "use client" solo cuando se requiera interactividad.
207 [List Paragraph] Una mutación que toca más de una tabla pasa por un RPC PL/pgSQL (security invoker).

209 [List Paragraph] No hardcodear strings de roles: usar ROLES.* de lib/constants.ts.
